# Roles in FOSS Projects

Free and Open Source Software (FOSS) projects are run by different types of people who can contribute to and run the software. The three main roles discussed in lecture are **users, contributors and maintainers**. Each role comes with different to do task and responsibilities within a project.

## Users

Users are people who use/run the software but does not contribute directly to its development. They are often the largest group involved in a FOSS project. Since the user group has experience using the software, they may discover problems or bugs while using it.

A user can contribute to the project by submitting a **bug/issue report**. A good bug/issue report can help developers understand the problem that exist and provide information needed to investigate it.

## Contributors

Contributors are people who are actively helping to improve a FOSS project. This can involve writing code, documentation or translations. Contributors may also help reproduce bugs reported by users.

For example, if a user reports a bug, a contributor may investigate the issue by trying to reproduce the same behaviour. Reproducing a bug helps determine whether the problem is real and can provide further details about its cause.

Contributors may also review code or other submissions made by other contributors.

## Maintainers

Maintainers are the owners or project leaders responsible for managing the project. They review contributions and decide which changes should be included in the project.

Some of their responsibilities include:

- Reviewing and merging pull requests
- Managing project releases
- Coordinating contributions
- Helping guide the direction of the project

## The relationship between these three roles can be summarized as follows:

| Role | Main Responsibility |
|---|---|
| User | Uses the software and may report bugs |
| Contributor | Helps improve the project through code, documentation, testing, or translations |
| Maintainer | Reviews contributions, manages releases, and leads the project |

## The Bus Factor

An important concept in FOSS projects is the **bus factor**. The bus factor refers to the number of critical people who would need to become unavailable before a project could no longer continue effectively.

A low bus factor means that a project depends heavily on only a few people. For example, if we lose one or two maintainers who understands an important part of the project, losing them could make it difficult to maintain or continue with the project/sofware.

So we can reduce the dependency and make the project more sustainable by having multiple contributors that has an understanding/knowledge of the project.
